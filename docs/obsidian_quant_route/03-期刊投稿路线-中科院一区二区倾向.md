# 期刊投稿路线：中科院一区/二区倾向

日期：2026-06-03

## 总体判断

如果目标是国际期刊、中科院一区/二区，EigenSkill 需要从“端侧 skill demo”重构为“LLM 量化数学方法”。当前最合适的论文题目不是 Swarm LLM，也不是业务 skill routing，而是：

```text
Sensitivity-Aware Rotational Mixed-Precision Quantization for Large Language Models
```

或：

```text
EigenSkill-Q: A Sensitivity-Guided Quantization Skill Router for Low-Bit LLM Inference
```

## 文章形态建议

### 论文 1：量化数学主文

题目候选：

```text
Sensitivity-Aware Orthogonal Rotation and Mixed-Precision Allocation for Low-Bit LLM Quantization
```

主贡献：

1. 统一的 Hessian/activation 加权量化误差目标；
2. 可学习或可构造正交旋转，用于 outlier redistribution；
3. 混合精度 bit allocation 算法；
4. 低秩 residual compensation；
5. 在 LLaMA/Qwen/SmolLM/Phi 等模型上做 2/3/4/8-bit 对比。

更适合 TNNLS / Neural Networks / Information Sciences。

### 论文 2：系统扩展文

题目候选：

```text
Edge-Aware Hybrid Quantized Runtime for Skill-Conditioned LLM Inference
```

主贡献：

1. quantization skill router；
2. C++/NEON/NPU micro-kernel；
3. memory bandwidth / latency / energy 测量；
4. 端侧模型部署。

更适合 ACM TECS / Journal of Systems Architecture / EAAI。

### 论文 3：Vision/架构文

题目候选：

```text
Cross-Medium Swarm LLMs: A Vision for Distributed Quantized Intelligence on Edge Devices
```

这篇只能作为愿景或综述，不适合作为当前第一篇主攻。

## 必须补齐的实验

### 模型

至少覆盖：

- SmolLM2-360M / 1.7B；
- Qwen2.5-0.5B / 1.5B；
- Phi-2 或 Gemma small；
- LLaMA-family small/open checkpoints，如果许可允许。

### 任务

量化论文不能只测自建 skills。应覆盖：

- WikiText / C4 perplexity；
- MMLU / ARC / HellaSwag / PIQA；
- GSM8K 或数学推理；
- HumanEval/MBPP 或代码；
- LongBench / Needle / RULER 这类长上下文；
- 自建 quantization stress test 作为补充。

### Baselines

至少对比：

- RTN；
- GPTQ；
- AWQ；
- SmoothQuant；
- OmniQuant；
- QuaRot；
- SpinQuant；
- KVQuant/KIVI，如果做 KV cache。

### Ablation

必须有：

- no rotation vs random rotation vs Hadamard/Givens/learned rotation；
- uniform bit vs mixed bit；
- with/without Hessian weighting；
- with/without low-rank residual；
- calibration size 16/32/64/128/512；
- cross-domain calibration：校准集和测试集不同域；
- latency/throughput/memory footprint。

## 期刊审稿人最可能问什么

1. 你的数学目标是否真的不同于 GPTQ/AWQ/QuaRot？
2. 你的旋转是否带来额外计算开销？能否融合进权重？
3. mixed precision 的 bit allocation 是否只是启发式？有没有理论保证？
4. 为什么不是简单多给敏感层 8-bit？
5. calibration 数据是否泄漏？
6. 是否只在小模型和合成任务上有效？
7. 是否在真实 low-bit kernel 上测了速度，而不是只测 fake quant？
8. 是否有显存、带宽、KV cache 的真实收益？

## 投稿前最低门槛

- 一个完整、无泄漏的 benchmark；
- 至少 3 个开源模型；
- 至少 5 个公开任务；
- 至少 5 条强 baseline；
- 数学目标函数 + 误差界或复杂度分析；
- 真实量化后推理，不只是模拟；
- 代码和配置可复现；
- 明确声明当前 EigenSkill skill demo 只是动机/附录。
