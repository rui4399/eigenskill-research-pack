## 必须同时写清楚的限制

这次训练是“完成的工程 PoC”，但不是论文主实验。

原因：

```text
train_n = 7200
eval_n = 1440
exact_train_eval_overlap = 1339
input_train_eval_overlap = 1339
unique_prompt_templates = 13
```

因此：

1. v2 包可以用于展示训练、LoRA、合并模型、INT8 dynamic 导出和 hybrid runtime。
2. v2 指标不能作为国际期刊/会议的泛化证据。
3. 不能声称已证明 EigenSkill 有强泛化能力。
4. 不能把 99.93% 写成量化算法效果。
5. 后续主线必须转向无泄漏公开 benchmark 与 LLM 量化数学。

## 训练目标的重新定义

后续训练不应继续扩大低熵业务 skill，而应训练/评估量化策略 skill：

```text
outlier_detect
hessian_probe
rotation_select
bit_allocate
kv_policy
residual_patch
```

这些 skill 对应模型量化流程中的决策，而不是家居命令或 JSON 修复。

## 下一步最小无泄漏训练

### 数据划分原则

```text
train templates != eval templates != test templates
train entities != eval entities where possible
calibration != validation != test
```

### 最小数据集

建议先做一个小但干净的数据集：

```text
data_eval/eigenskill_quant_v0/
  train.jsonl
  eval.jsonl
  test.jsonl
  audit.json
```

任务不再是业务命令，而是量化决策：

| task | 输入 | 输出 |
| --- | --- | --- |
| outlier_detect | layer stats / channel max / kurtosis | outlier group ids |
| bit_allocate | sensitivity + memory budget | per-layer bit policy |
| rotation_select | covariance / block variance | rotation family |
| residual_patch | error spectrum | rank r policy |
| kv_policy | context length + K/V stats | KV quant policy |

### 先跑的 baseline

```text
uniform INT4
uniform INT3
random mixed precision
activation-norm sensitivity
rate-distortion allocation
```

### 训练/评估成功标准

第一阶段不要追求大模型 SOTA，只要求：

```text
1. split audit 通过，无 train/eval exact overlap
2. 至少 3 个 quant policy skills
3. LoRA 或小分类器能在 eval 上泛化
4. 指标和 prompt 泄漏审计一起写入报告
5. 产出可作为论文方法动机，而不是主 SOTA 结果
```
