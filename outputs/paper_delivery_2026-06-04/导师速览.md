# EigenSkill-Q 导师速览

日期：2026-06-04

## 一句话定位

EigenSkill-Q 当前最稳的论文主线不是“端侧蜂群大模型”或“已证明的
Eigen-Routing”，而是：

```text
面向混合精度 LLM 量化的可验证策略旁路：
把低熵、可审计、强数值规则的量化策略从 LLM token 生成中剥离，
交给 Python/C++ policy kernel 执行。
```

这个方向更适合数学、机器学习、强化学习和量化方向的论文叙事。

## 当前已经完成的实证结果

### 1. 无泄漏量化策略数据集

数据集：`data_eval/eigenskill_quant_v1`

包含五类 quantization-policy skills：

```text
outlier_detect
bit_allocate
rotation_select
residual_patch
kv_policy
```

规模：

```text
train: 1200
eval:   400
test:   400
```

审计结果：

```text
train/eval/test exact-row overlap = 0
train/eval/test input overlap     = 0
```

这比早期 v2 routing split 强很多。早期 v2 存在严重 overlap，只能当工程
PoC，不能当泛化实验。

### 2. Python 严格 oracle

Python deterministic evaluator 在 eval/test 上达到：

| split | rows | exact_json | decision_exact | parse_error |
|---|---:|---:|---:|---:|
| eval | 400 | 1.000000 | 1.000000 | 0.000000 |
| test | 400 | 1.000000 | 1.000000 | 0.000000 |

这里的 `exact_json` 是严格 JSON 对齐，包括 `risk`、`score` 等辅助数值字段。

### 3. C++ policy kernel

新增 C++ 程序：

```text
inference_cpp/src/quant_policy_bypass.cpp
```

编译：

```powershell
powershell -ExecutionPolicy Bypass -File .\inference_cpp\build-msvc.ps1 -Target quant-policy
```

结果：

| split | rows | policy_fields_exact | decision_exact | parse_error | throughput |
|---|---:|---:|---:|---:|---:|
| eval | 400 | 1.000000 | 1.000000 | 0.000000 | 8261 rows/s |
| test | 400 | 1.000000 | 1.000000 | 0.000000 | 6924 rows/s |

C++ 版本重点验证“关键策略字段”是否完全一致，不冒充严格 JSON oracle。

### 4. 小模型 LoRA 负结果

SmolLM2-360M 的短周期 LoRA smoke test：

```text
json_valid:     35%
schema_ok:       0%
exact_json:      0%
decision_exact:  0%
```

这个负结果反而支持论文动机：确定性数值策略不应该完全依赖小模型生成。

### 5. Qwen2.5-1.5B loss-sensitive 量化证据

本地缓存的 `Qwen2.5-1.5B-Instruct` 已完成 fake weight quantization 质量诊断。
这比 SmolLM2-360M 更接近可汇报的主线，但仍不是 packed runtime。

| dataset | FP16 | uniform INT4 | uniform INT3 | 2p loss-sensitive | 8p loss-sensitive | consensus |
|---|---:|---:|---:|---:|---:|---:|
| WikiText2-64 | 12.8516 | 17.2441 | 273.9454 | 16.1788 | 15.7520 | 15.7966 |
| C4-64 | 18.1669 | 23.9949 | 293.8201 | 23.2682 | 22.3620 | 22.4891 |
| WikiText2-128 | 13.1290 | 17.4996 | 232.6215 | 16.6503 | 16.0781 | 16.1356 |

关键点：

- 8-prompt loss-sensitive allocation 在三个切片上都优于 uniform INT4；
- 2-prompt 与 8-prompt 的 high-bit module Jaccard 为 `0.6351`，说明 calibration stability 需要报告；
- consensus allocation 更稳定，但当前 PPL 略弱于直接 8p allocation；
- 这仍是 fake quant 质量诊断，不能声称真实 INT4/INT3 显存、延迟或能耗。

### 6. C++ low-bit kernel 进展

C++ 侧已经不只是 policy evaluator。新增通用 row-scaled signed low-bit API：

```text
PackedLowBitMatrix
pack_lowbit_per_row(bits=2..7)
unpack_signed_bits
lowbit_dequant_gemv
```

WSL/g++ 11.4 验证通过：

```text
cmake build: passed
ctest: passed
quant_kernel_verify --dim 256 --active-rows 16: ok=true
```

但 benchmark 显示 naive scalar bit-unpack INT3/INT4 GEMV 仍慢于 AVX2 FP32 dense
GEMV。这个结果要诚实写成“低比特 kernel API 与负向系统基线”，不能包装成速度收益。

### 7. GPU 资源边界

本机 GPU 是 NVIDIA GeForce RTX 5070 Laptop GPU，约 8.15 GiB 显存。Qwen2.5-1.5B
的 WikiText2-128 多配置 `--reuse-model` 评估曾短时达到 `7296/8151 MiB`，约
89.5%，超过 85% 目标。后续 1.5B 以上实验应拆分 config 或采用更省显存路径。

## 推荐论文主线

建议标题：

```text
EigenSkill-Q: Verifiable Policy Bypass for
Sensitivity-Rate-Distortion Guided Mixed-Precision LLM Quantization
```

核心假设：

```text
LLM 适合做 semantic routing 和解释；
低熵、强数值约束、可验证的量化策略适合交给 policy kernel；
policy kernel 可以是确定性规则、表驱动 C++、或经过约束训练的 bandit/RL policy。
```

## 数学主线

量化策略可写成约束优化：

```text
minimize    sum_l D_l(W_l, A_l, Q_l) + alpha C_l(b_l, R_l, o_l, r_l, k_l)
subject to  sum_l M_l(b_l, k_l) <= B
            sum_l T_l(b_l, R_l, r_l, k_l) <= T
            Risk_l(o_l, b_l, k_l) <= epsilon_l
```

其中：

- `b_l`：bit width / format；
- `R_l`：rotation / preconditioner；
- `o_l`：outlier protection；
- `r_l`：residual correction rank；
- `k_l`：KV-cache policy；
- `D_l`：Hessian/Fisher/activation-MSE 加权 distortion；
- `M_l/T_l`：memory/latency；
- `Risk_l`：outlier 和可靠性风险。

在线策略可进一步写成 constrained contextual bandit：

```text
maximize    E[Reward(x_t, a_t)]
subject to  E[Memory(x_t, a_t)] <= B
            E[Latency(x_t, a_t)] <= T
            P(QualityDrop(x_t, a_t) > delta) <= eta
```

这会把项目从“工程 if-else”提升为“可学习、可约束、可验证的量化控制层”。

## 适合投的方向

用户要求避开 NeurIPS / MLSys。更现实的 CCF-A 候选：

| 方向 | 候选 | 需要补强 |
|---|---|---|
| 机器学习/优化 | ICML | 数学形式、rate-distortion、bandit/RL 实验要强 |
| 人工智能 | IJCAI / AAAI | 策略学习 + 量化实验 + 可靠工具执行 |
| NLP/LLM serving | ACL | 把 policy bypass 写成可靠工具调用/结构化执行 |
| 期刊 | AI / TPAMI / JMLR | 需要完整理论、强 baseline、长实验周期 |

严格说明：TNNLS 很强，但 CCF AI 官方页列为 B 类，不建议在“CCF-A”包装里
主推，除非学校另外按中科院分区或本校名单认可。

## 目前不能声称的内容

当前不能写成已经完成：

- 真正 Transformer 层的 `O(d)` eigen-routing；
- 穿过 LayerNorm / SwiGLU / residual nonlinear dynamics 的不变子空间证明；
- 超过 GPTQ/AWQ/SmoothQuant/QuaRot/SpinQuant/QuIP/AQLM 的量化效果；
- 真实 edge board / ARM / NPU latency 和 energy；
- 声学通信、物理蜂群、跨介质系统实现。

这些可以保留为 future work 或远景，不应放进主贡献。

## 下一阶段必须补的实验

1. 在 Qwen2.5-1.5B 已有 fake-quant 正结果基础上，补真实 packed quant baseline。
2. 计算 calibration statistics：activation MSE、outlier score、
   Hessian/Fisher proxy、KV sensitivity。
3. 对比 uniform/RTN、GPTQ、AWQ、SmoothQuant、QuaRot/SpinQuant。
4. 做 policy ablation：
   - 无 policy；
   - heuristic policy；
   - C++ deterministic policy；
   - learned bandit/RL policy。
5. 报告 PPL、task accuracy、memory、latency、policy overhead。
6. 如果还要写 edge，必须上真实硬件再谈 latency/energy。
